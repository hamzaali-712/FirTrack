# FitTrack — 3D, Exercise Text, Imagery and Font Licensing Policy

> **Project:** FitTrack · **Version:** 2.0 planning baseline · **Prepared:** 2026-11-18  
> **Status:** Design/specification only; no implementation, live deployment, production security, test pass, medical accuracy review, or third-party asset license is claimed.  
> **Constraints:** 2 developers · 8-week delivery window · MongoDB, Express.js, React.js, Node.js (MERN) · responsive web app.  


## Purpose and non-negotiable rules
No exercise picture, GIF, motion clip, 3D mesh, anatomical texture, screenshot, illustration, sound or webfont can be republished solely because it was accessible on the internet. Content provenance and license permission must be documented **before** publishing or bundling in a public repository, deployed website or university submission. The user supplied a screenshot for **inspiration** only; do not copy its logotype, images or contact details.

## 1. Asset intake checklist
| Evidence | Required entry |
|---|---|
| Source / creator | Name or organization, original URL, retrieval date |
| License | Exact terms and grant, version and conditions |
| Rights | Public website use, redistribution, derivative work, screenshots/video demos, commercial use if relevant |
| Attribution | Where and how credit must appear; do not omit required notices |
| Asset type | Model, skeleton/rig, clip, texture, poster, image, font, written instruction |
| Data fingerprint | SHA-256 of distributed file and revision |
| Reviewer | Who checked license; date; screenshot/archived evidence of terms |
| Anatomy/technique | Exercise-to-clip match review, limitations and reviewer name |
| Status | Candidate / License checked / Form reviewed / Approved / Rejected |

## 2. Candidate reference sources (no asset has been verified in this pack)
- **Google Fonts Manrope:** https://github.com/google/fonts/tree/main/ofl/manrope — Google Fonts repository includes OFL metadata/license; follow license when bundling actual font. No font binaries supplied by this documentation set.
- **Adobe Mixamo:** https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html — official FAQ explains current use options, but individual asset rig suitability, distribution and character/animation rights must still be reviewed at acquisition.
- **glTF standard:** https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html — **format specification**, not a blanket license for any 3D asset.
- **W3C WCAG:** https://www.w3.org/TR/WCAG22/ — accessibility requirements, not a media license.
- **Exercise datasets online:** each provider has separate terms; never bulk scrape or mirror without permission, and check attribution and derivative distribution.

## 3. Licensed content workflow
For each new asset: shortlist -> source authenticity -> detailed licensing decision -> hash and secure staging -> compatibility test -> factual/movement review -> performance optimization -> controlled publication. Only the artifact specifically approved in the register can be marked animation-ready. Updating the rig/clip/texture triggers renewed compatibility and review checks.

## 4. Written exercise instructions
Write original plain-language descriptions based on credible, reviewable training sources; cite provenance internally. Avoid direct copy-paste of copyrighted third-party instructions. Include setup, movement, safe/controlled return and general cautions; do not promise injury prevention or personalized medical advice.

## 5. Public website/legal content
Do not invent “as seen in”, testimonial reviews, user counts, social accounts, contact email, privacy policy legal terms, or accessibility certifications. Add pages only when content is actually authored and reviewed. A university demo with fake accounts should be explicitly identified as such when demonstrated.

## 6. Right to remove and replace
If permissions cannot be verified or rights are withdrawn: unpublish the asset immediately, preserve exercise instructions and user history, mark animation unavailable, update the asset register and issue a content-version change. Never delete workout records due to media removal.
